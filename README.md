# aide

먼저 말을 걸어주는 개인 비서의 **1단계**.
정해진 주기로 깨어나서, 코드로 싸게 검사하고, 알릴 게 있을 때만 텔레그램으로 알려줍니다.

> 현재 단계: **1단계 (알림 전용)** — AI 호출 없음, 메일 접근 없음, 수신(명령) 없음.
> 전체 계획은 [docs/ROADMAP.md](docs/ROADMAP.md), 설계는 [ARCHITECTURE.md](ARCHITECTURE.md), 보안 규칙은 [SECURITY.md](SECURITY.md).

## 1단계가 하는 일
| 검사 | 내용 | 중복 방지 |
|---|---|---|
| 작업 폴더 | 감시 중인 git 폴더에 커밋 안 된 변경이 N개 이상이면 알림 | 폴더당 하루 1회 |
| 뉴스 키워드 | RSS 피드 제목/요약에 키워드가 있으면 알림 | 기사당 1회 |

- 조용한 시간(기본 22:30–07:00)에는 점검만 건너뜁니다. 쌓인 알림은 아침에 한 번에 옵니다.
- 알릴 게 없으면 **아무 말도 하지 않습니다.** 조용한 것이 정상입니다.

## 빠른 시작 (Windows)
```bat
cd C:\dev\aide
copy config.example.json config.json
copy .env.example .env
```
1. `config.json` 을 열어 감시할 폴더와 키워드를 수정합니다.
2. `.env` 에 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` 를 넣습니다. (**.env 는 git 에 올라가지 않습니다**)
3. 점검과 시험 실행:
```bat
set PYTHONPATH=%CD%\src
python -m aide selfcheck
python -m aide heartbeat            :: 드라이런. 화면에만 출력, 전송/상태 변경 없음
python -m aide heartbeat --send     :: 실제 전송
```
4. 정상이면 30분마다 자동 실행 등록: `scripts\register_task.bat`

## 테스트
```bat
set PYTHONPATH=%CD%\src
python -m unittest discover -s tests -v
```
외부 의존성 없음 (Python 3.9+ 표준 라이브러리만 사용).

## 텔레그램 봇 준비
1. 텔레그램에서 `@BotFather` → `/newbot` → 토큰 받기
2. 만든 봇에게 아무 메시지나 보낸 뒤 `https://api.telegram.org/bot<토큰>/getUpdates` 를 열어 `chat.id` 확인
3. 두 값을 `.env` 에만 저장 (코드·설정 파일·채팅에 붙여넣지 말 것)

## 버튼 응답 (3a)
알림 아래의 [확인] [무시] [나중에] 버튼은 `python -m aide poll` 이 받아 기록합니다.
- 예약 작업(`scripts\run_heartbeat.bat`)이 점검 직전에 `poll` 을 먼저 실행하므로 최대 30분 안에 반영됩니다.
- 즉시 반영하려면 `scripts\register_poll_watch.bat` 로 백그라운드 감시를 등록하세요(창 없이, 관리자 권한 불필요, 꺼지면 1분 안에 자동 재시작). 지금 바로 켜려면 `schtasks /Run /TN "aide-poll-watch"`. 감시가 켜져 있으면 예약된 `poll` 은 자동으로 건너뜁니다(텔레그램은 동시에 한 곳만 읽을 수 있음).
- 버튼은 기록만 바꿉니다. 명령 실행은 3b 에서 별도로 엽니다.

## 읽기 전용 명령 (3b)
`config.json` 에 `"commands": ["오늘", "일정", "마감", "메일", "날씨"]` 를 넣으면 **본인의 개인 채팅**에서 아래 명령을 바로 물어볼 수 있습니다(기본은 꺼짐, 비어 있으면 3a 와 동작이 완전히 같습니다).

| 명령 | 영문 | 내용 |
|---|---|---|
| `/오늘` | `/today` | 오늘 날씨·일정 |
| `/일정` | `/week` | 오늘부터 7일 일정 (끝 시각·기간·장소·겹침 표시, 아래 "일정 표시" 참고) |
| `/마감` | `/due` | 7일 이내 접수 마감 공지 |
| `/메일` | `/mail` | 최근 안 읽은 메일 (보낸 사람·제목만) |
| `/날씨` | `/weather` | 오늘 날씨 |
| `/도움` | `/help`, `/start` | 켜져 있는 명령 목록 (항상 사용 가능) |

- **본인의 개인 채팅**에서 보낸 **글자 메시지**만 받습니다. 다른 사람, 그룹, 전달된 메시지, 사진·파일은 조용히 무시합니다(답장도 하지 않음).
- `commands` 목록에 없는 이름은 "모르는 명령이에요" 로만 답합니다 — 꺼진 명령은 모르는 명령과 똑같이 취급합니다.
- aide 가 꺼져 있던 동안 쌓인 명령(10분 넘게 지난 것)은 실행하지 않고 몰렸다는 안내만 한 번 보냅니다. 한 번에 최대 3개, 한 시간에 최대 20개까지만 실행하고 넘으면 안내 후 조용히 무시합니다.
- 명령은 **읽기 전용**이며 구글 권한도 읽기 전용(`*.readonly`)만 씁니다. 상태 파일을 바꾸는 일도, 다른 곳에 보내는 일도 없습니다.
- 자세한 위협·대응은 `SECURITY.md` 의 "수신 채널 (3b)".

## 문장으로 묻기 (대화 C1)
`config.json` 에 `"chat_enabled": true` 를 넣으면(기본 꺼짐, `llm_enabled` 와 `commands` 도 필요) 명령어 대신 **그냥 문장**으로 물어볼 수 있습니다. `.env` 의 `ANTHROPIC_API_KEY` 를 씁니다.

- 예: `다음 주 화요일 일정 뭐야?` / `치과 언제였지?` / `내일 날씨` / `학교 메일 3일치` / `이번 주 마감 공지`
- 조회만 합니다: 일정·마감·메일·날씨·오늘 요약·도움. 보내기·삭제·수정은 못 합니다("조회만 할 수 있어요").
- 답 첫 줄에 어떻게 알아들었는지 나옵니다. 예: `▸ 찾아본 것: 10/06(화)~10/08(목) 일정 · 개인 · '치과'`. 값이 범위를 벗어나 고쳐 찾았으면 `※` 줄로 알려 줍니다. 틀리게 알아들었으면 문장을 바꿔서 다시 물어보세요.
- 못 알아들었을 때는 이유별로 알려 줍니다(이해 못 함 / 날짜가 범위 밖 / 꺼진 조회 / 연결 안 됨 / 읽기만 가능). 연결이 안 됐거나 키가 없을 때는 하루 횟수를 쓰지 않습니다.
- 한계: 일정은 지난 62일~앞으로 60일, 한 번에 31일까지. 메일 찾기는 최근 7일 안 읽은 메일 최신 20건의 제목·보낸 사람 안에서만. 날씨는 오늘부터 6일 뒤까지 하루씩(설정된 위치). 오전/오후 구분과 이전 대화 기억은 아직 안 됩니다.
- Anthropic 으로 가는 것은 **선생님이 쓴 문장뿐**입니다. 메일·일정 내용은 모델에 보내지 않고, 조회는 `/명령` 과 같은 읽기 전용 코드가 합니다.
- 한 문장은 200자 이하, 한 시간에 10번, 하루 `chat_max_per_day`(기본 20)번까지. 넘으면 안내만 나가고 `/명령` 은 그대로 됩니다. 한 번 부를 때 아주 적은 API 비용이 듭니다.
- `/` 로 시작하는 글은 항상 명령으로만 처리됩니다. `chat_enabled` 를 끄면 문장은 "모르는 명령이에요" 로 답합니다.
- 자세한 설계·보안 검토는 `ARCHITECTURE.md` 의 "대화 C1", `SECURITY.md` 의 "대화 C1".

## 일정 표시 (B1)
일정 줄은 아침·저녁·`/오늘`·`/일정`·문장 질문 모두 같은 모양입니다: `09:00~10:30 회의 @본관`, 다음 날까지 가면 `18:00~10/22 10:00 숙박`, 종일 여러 날은 `종일 ~10/23 출장`. 전날 시작해 이어지는 일정은 `(진행 중, ~10/23) 출장` 으로 나옵니다. 같은 날 시간이 겹치는 일정(끝 시각이 있는 것끼리)은 줄 끝에 `⚠ 겹침` 이 붙습니다. 종일·진행 중 일정은 겹침에서 빠집니다. 장소와 끝 시각은 AI(2b)에는 보내지 않습니다. 빈 시간 찾기는 아직 없습니다.

## 구글 할 일 (읽기 전용)
`config.json` 의 `"tasks_accounts": ["개인"]` 에 적은 계정의 구글 할 일을 읽습니다(기본 꺼짐, 비어 있으면 아무것도 읽지 않음). 메모는 읽지 않고, 완료 처리나 추가는 못 합니다.

1. 구글 Cloud 프로젝트에서 **Google Tasks API** 를 켭니다.
2. PC 에서 `python -m aide google-login --account 개인 --tasks` 를 실행하고, 동의 화면에서 **할 일 권한까지 체크**한 뒤 허용합니다. 끝나면 "할 일 권한이 허용되지 않았어요" 대신 "(캘린더, Gmail, 할 일)" 이 나와야 합니다.
3. 만들어진 토큰 파일(`data/google_token_personal.json`)을 서버로 복사하고 `chown aide:aide`, `chmod 600` 을 합니다.
4. 서버 `config.json` 에 `"tasks_accounts": ["개인"]` 을 넣고 `commands` 에 `"할일"` 을 더한 뒤 `aide-watch` 를 재시작합니다. `python -m aide selfcheck` 의 `tasks` 줄이 "권한 있음" 이어야 합니다.

- 아침 인사 `■ 할 일 (오늘까지)`(지난 것·오늘 것, 날짜 없는 것은 맨 위 하나만 보여 주고 나머지는 개수로), 저녁 정리 `■ 내일까지 할 일`(일요일은 `■ 다음 주까지 할 일`).
- `/할일`(또는 `todo`): 지난 것과 7일 이내 할 일, 날짜 없는 할 일은 맨 위 하나와 나머지 개수. 문장으로도 됩니다: `이번 주 할 일`, `보고서 할 일 언제까지야?`.
- 할 일 제목은 텔레그램 본인 채팅으로만 가고, AI(Anthropic)에는 보내지 않습니다.
- 자세한 설계·보안 검토는 `ARCHITECTURE.md` 의 "구글 할 일", `SECURITY.md` 의 "구글 할 일".

## 먼저 챙기기 (nudges)
`config.json` 에 `"nudges": ["busy", "prep"]` (기본 꺼짐)로 아침·저녁 메시지 머리줄 아래에 한 줄씩 붙입니다. LLM·새 알림 없음.
- `busy`(아침): `⚠ 바쁜 날: 일정 6개 · 겹치는 일정 2개 · 오늘까지 할 일 3개` — 일정이 `busy_events`(기본 5)개 이상이거나 겹침이 있을 때만.
- `prep`(저녁): `▶ 내일 준비: 첫 일정 08:30~10:00 출장 @본관 · 내일까지 할 일 2개` — 내일 첫 일정과 할 일이 있을 때만(일요일은 월요일 기준).
할 일 수는 구글 할 일(`tasks_accounts`)이 켜져 있을 때만 들어갑니다.

## GitHub 아침 브리핑 (읽기 전용)
`config.json` 의 `"github_accounts": ["boundaryx01-uniquelife", "foruniquelife00"]` (기본 `[]` = 꺼짐, 최대 5개)에 적은 계정이 가진 저장소를 **전부 자동으로** 봅니다(저장소별 설정 없음, 보관된 저장소 제외). 아침 인사의 할 일 구역 다음에 어제(KST 00:00~24:00) 활동이 나옵니다. 아무 일도 없었으면 구역이 빠집니다. AI(LLM)는 쓰지 않습니다.
```
■ GitHub (어제 11/06)
⚠ briefing-bot: 자동 작업 실패 1 (Daily 3D News Bot)
• aide: 커밋 5 · PR 병합 2 · 열린 PR 1
```
- ⚠ 줄은 GitHub Actions 실패(푸시가 없어도 예약 실행은 있으므로 모든 저장소 대상), • 줄은 어제 푸시된 저장소의 커밋·병합 PR·열린 PR **개수**입니다. 커밋 메시지·PR 제목은 가져오지도 표시하지도 않습니다. 최대 10줄 + `…외 N개`. 같은 이름의 저장소가 두 계정에 있으면 `계정/저장소` 로 나옵니다.
- 토큰이 없으면 `GitHub(계정): 토큰 없음`, 401/403·연결 오류면 `GitHub(계정): 불러오지 못함 (토큰 확인)` 한 줄만 나오고 아침 인사는 그대로 나갑니다.

토큰 만들기(계정마다 따로, 그 계정으로 로그인한 상태에서):
1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token.
2. Resource owner 는 그 계정, Repository access 는 **All repositories**, Permissions 의 **Metadata · Contents · Pull requests · Actions** 를 모두 **Read-only** 로 둡니다(다른 권한은 주지 않습니다). 만료일은 길게(예: 1년) 잡고 달력에 적어 둡니다.
3. `.env` 에 `GITHUB_TOKEN_` + 계정 이름을 **대문자로, `-` 는 `_` 로** 바꾼 이름으로 넣습니다. 예: `GITHUB_TOKEN_BOUNDARYX01_UNIQUELIFE=...`, `GITHUB_TOKEN_FORUNIQUELIFE00=...` (`.env.example` 참고). 서버에서 쓰려면 서버의 `.env` 에 넣고 `aide-watch` 를 재시작합니다.
4. `python -m aide selfcheck` 의 `github` 줄이 계정마다 "토큰 있음" 이어야 합니다(값은 출력하지 않음).
- 저장소 58개 기준 호출은 계정 목록 1회 + 저장소마다 Actions 1회 + 어제 푸시된 저장소마다 3회 정도입니다. 미리보기(`python -m aide morning`)도 실제로 GitHub 를 부릅니다.

## LLM 중요도 판단 (2a)
`config.json` 에 `"llm_enabled": true` 를 넣고 `.env` 에 `ANTHROPIC_API_KEY` 를 넣으면, 30분 점검 때마다 새 메일·공지·뉴스 항목의 중요도(높음/보통/낮음)를 LLM 이 매겨 **순서만** 바꿔 줍니다(기본 꺼짐).
- 높음은 "■ 중요 (AI 판단)" 섹션으로 맨 위에, 낮음은 각 섹션 맨 아래로. 항목을 숨기거나 더하지 않으며, 표시되는 글자는 항상 원래 데이터입니다.
- 미리보기(`python -m aide heartbeat`, `--send` 없음)는 **LLM 을 부르지 않습니다** — 돈이 나가는 호출이라 반복 실행해도 비용이 들지 않습니다. 실제 전송(`--send`) 때만 호출합니다.
- `llm_sources`(기본 메일·공지·뉴스), `llm_exclude_accounts`(예: `["학교"]`), `llm_max_calls_per_day`(기본 30회), `llm_model`(기본 `claude-haiku-5-5`), `llm_profile`(선생님이 적는 참고용 한 줄 설명)로 조절합니다.
- 메일 제목·발신자, 공지·뉴스 제목이 Anthropic 서버로 전달됩니다. 켜기 전에 Anthropic 의 데이터 보존·학습 정책을 확인하세요.
- 키가 없거나, 하루 호출 상한을 넘었거나, 응답 형식이 어긋나면 지금과 똑같은 순서로 보냅니다(실패해도 알림 자체는 막히지 않음).
- 자세한 설계·보안 검토는 `ARCHITECTURE.md` 의 "LLM 판단 (2a)", `SECURITY.md` 의 "LLM 판단 2a".

## 오늘의 핵심 (2b)
`config.json` 에 `"llm_highlights": ["morning", "evening"]` 를 넣으면(기본 꺼짐, 2a 와 같은 `llm_enabled`·`ANTHROPIC_API_KEY` 필요), 아침 인사·저녁 정리 맨 위에 "■ 오늘의 핵심 (AI 판단)" 이 최대 3줄 붙습니다(저녁은 "내일의 핵심", 일요일 저녁은 "이번 주 핵심").
- **모델은 글을 쓰지 않습니다.** 항목 번호와 이유 코드(마감 임박/준비 필요/일정 겹침/날씨 주의/중요)만 고르고, 화면에 나오는 문장은 aide 가 원래 일정·마감 글자와 고정 문구로 조립합니다. 원래 목록은 그대로 아래에 남고, 고를 게 없으면 섹션 자체가 생략됩니다.
- 후보(오늘/내일/이번 주 일정 + 마감 공지)가 4개 미만이면 애초에 호출하지 않습니다.
- `llm_exclude_accounts` 의 계정 일정은 후보에서 빠집니다(2a 와 같은 설정 공유).
- 미리보기는 2a 와 같이 **LLM 을 부르지 않습니다.** 실제 전송 때만 호출하고, 하루 호출 상한은 2a 와 합산됩니다.
- 자세한 설계·보안 검토는 `ARCHITECTURE.md` 의 "LLM 판단 (2b)", `SECURITY.md` 의 "LLM 판단 2b".

## 내 메일 규칙 (선호 학습 L1)
`config.json` 에 `"rules_enabled": true` 를 넣으면(기본 꺼짐, `evening_hour` 도 필요) 메일 알림 아래에 **[🧹 정리]** 버튼이 생깁니다. 누르면 그 알림에 나온 발신자(주소 포함)가 버튼으로 나오고, 하나를 고른 뒤 아래 중 하나를 누릅니다.

| 선택 | 동작 |
|---|---|
| 알림제외 | 그 주소의 메일을 알림에 넣지 않습니다(메일함은 그대로). |
| 유지 | 규칙을 두지 않습니다(있던 규칙은 지움). |
| 중요 | 항상 맨 위 "■ 중요 (내 규칙)" 에 보여 줍니다. |
| 수신거부 | Gmail 에서 그 메일을 열어 드립니다. 거기서 Google 의 "수신거부"를 직접 누르세요. aide 는 발신자에게 아무것도 보내지 않습니다. |

- 규칙은 **주소 하나 단위**이고(도메인 전체는 불가), `mail_senders` 에 직접 적은 발신자는 알림제외보다 우선합니다.
- 규칙 목록·삭제: 텔레그램의 [📋 규칙 목록] 또는 `python -m aide rules` / `python -m aide rules --remove <id>`.
- **일요일 저녁 정리**에 "■ 걸러낸 것 (지난 7일)" 이 발신자별 건수로 나옵니다. 잘못 걸러진 규칙을 알아채는 안전망이라 따로 끌 수 없습니다.
- `"mail_bulk_fold": true` 를 함께 넣으면 헤더로 광고·정기 메일(수신거부 헤더 등)로 보이는 메일 중 규칙이 없는 것을 한 줄로 접어 `광고·정기 메일 3건: A, B, C` 로 보여 줍니다. 본문은 읽지 않습니다. 접힌 메일만 있으면 알림을 보내지 않고 다음 알림에 함께 실립니다.
- 규칙은 `data/rules.json`(깃 제외)에 저장됩니다. `rules_enabled` 를 끄면 저장된 규칙도 즉시 적용이 멈춥니다.
- LLM 을 쓰지 않습니다. 자세한 설계·보안 검토는 `ARCHITECTURE.md` 의 "선호 학습 L1", `SECURITY.md` 의 "선호 학습 L1".

## 뉴스 시각과 장중 특징주
- `"news_hours": [7, 12]` — 일반 뉴스(`news_feeds`)를 이 시각에만 보냅니다. 비워 두면(기본) 점검할 때마다 새 기사를 보냅니다.
- `"market_queries": ["특징주", "상한가", "거래량 급증", "테마주", "장중 시황"]` — 구글 뉴스 검색에서 **평일 09:00~16:00** 점검(30분마다)마다 최근 기사를 찾아 `■ 장중 특징주` 섹션으로 보냅니다. 비워 두면(기본) 꺼짐.
  - 같은 종목 기사가 여러 언론사에서 나오면 한 줄로 합칩니다: `한국전력 · 호실적에 상한가 근접 (기사 3건)`. 한 종목은 하루에 한 번만 알립니다.
  - `market_exclude`(기본: 리딩방, 무료 추천, 카톡방, 수익 보장)가 들어간 기사는 뺍니다. `market_max_age_hours`(기본 3)보다 오래된 기사도 뺍니다.
  - 구글 뉴스 RSS는 실제 보도보다 수십 분 늦을 수 있습니다. 실시간 시세·거래량 순위는 이 기능의 범위가 아닙니다. 공휴일은 구분하지 않습니다.
  - 참고 자료일 뿐 투자 판단이나 추천이 아닙니다. LLM(Anthropic)에는 보내지 않습니다.
- 드라이런(`python -m aide heartbeat`)은 시각·요일 제한을 무시하고 지금 무엇이 나오는지 보여 줍니다.

## 뉴스 선정 기준
1. `news_feeds` 의 RSS 에 있는 기사만 후보가 됩니다.
2. 제목·요약에 `news_keywords` 중 하나가 (대소문자 무시, 부분 일치) 들어 있어야 합니다.
3. 발행 시각이 `news_max_age_hours`(기본 36)보다 오래된 기사는 제외합니다. 날짜를 읽을 수 없는 기사는 제외하지 않습니다.
4. 같은 기사(ID/주소)와, 매체명을 뗀 제목이 같은 기사는 한 번만 보냅니다. 다른 매체가 같은 제목으로 다시 내도 보내지 않습니다. 표현이 조금이라도 다르면 다른 기사로 봅니다.
5. 새 기사 순서로(최신 먼저) 한 번에 `max_items_per_digest` 건까지 보냅니다.
## 로그 파일

- `data\poll_watch.log`: 버튼 즉시 감시의 기록 (감시가 파일을 계속 열어 두므로 분리)

## 아침 인사 (1.5)
`python -m aide morning` 은 어제 커밋 요약과 커밋 안 된 변경이 많은 폴더를 한 줄씩 보여 줍니다 (기본은 미리보기, 전송 안 함).
`--send` 로 텔레그램에 보내며 하루에 한 번만 갑니다. 조용한 시간(기본 22:30~07:00)에는 건너뜁니다.
설정 시 날씨(Open-Meteo)와 오늘 구글 캘린더 일정(읽기 전용)도 함께 보냅니다 → `docs/GOOGLE_SETUP.md`. 일정/날씨 조회가 실패해도 인사는 갑니다.
30분 점검 작업(`run_heartbeat.bat`)이 마지막에 `morning --send` 를 함께 실행하므로 별도 예약이 필요 없습니다. 조용한 시간이 끝난 뒤 첫 점검(최대 30분 안)에 하루 한 번만 전송됩니다. (`register_morning.bat` 은 관리자 권한이 필요해 쓰지 않습니다.)

## 기관 공지·마감 감시
`config.json` 의 `notice_pages` 에 로그인 없이 열리는 공지 목록 페이지 주소를 넣으면, 30분 점검 때 새 글을 알려 줍니다.
- 제목에 `notice_keywords`(공모·모집·신청·접수·연수·공고·대회·전시회·지원사업·발명·메이커 등)가 있어야 합니다.
- 제목에 `notice_exclude`(예: 임용·수능·학점은행제·원서접수)의 단어가 있으면 제외합니다. 제외된 글은 페이지당 개수(`notice_max_per_page`)를 쓰지 않습니다.
- 행에 `~2026-10-12` 같은 접수 기간이 보이면 마감일을 알려 주고, 지난 건 제외, 마감 3일 전·1일 전에 한 번씩 다시 알립니다.
- 처음 등록하면 기존 글이 페이지당 최대 `notice_max_per_page`(기본 5)건 한 번 올 수 있습니다.
- 사이트마다 HTML 이 달라 먼저 시험하세요: `python -m aide notices` (전송·기록 없음). 0건이거나 엉뚱하면 알려 주세요(사이트별로 조정).
- 서버에서 완성된 HTML 로 주는 페이지만 읽습니다(자바스크립트로 그리는 페이지는 못 읽음). 로그인 필요한 게시판은 지원하지 않습니다.

## 메일 알림 (읽기 전용, 허용 발신자만)
`config.json` 에 `"mail_enabled": true`, `"mail_senders": ["pen.go.kr", "someone@site.kr"]` 를 넣으면 **그 발신자**가 보낸 **안 읽은 받은편지함 메일**(최근 2일)의 `보낸 사람: 제목` 한 줄만 알려 줍니다.
- 본문·첨부·스니펫은 가져오지 않습니다(헤더 From/Subject 만 요청). 허용 목록에 없는 메일은 조회 자체를 하지 않습니다.
- 알림에는 Gmail 링크가 붙고, 눌러서 열어 보는 것은 선생님입니다. aide 는 메일을 읽음 처리·삭제·전송하지 않습니다(권한이 읽기 전용).
- 메일 제목이 텔레그램(외부 서비스)으로 전달됩니다. 민감한 발신자는 목록에 넣지 마세요.
- 설정: `docs/GOOGLE_SETUP.md` 의 "Gmail 추가" 를 따라 Gmail API 를 켜고 `python -m aide google-login` 을 **다시** 실행해야 합니다.

### 시간대별 새 메일 요약 (허용 발신자 없이)
`"mail_enabled": true` 와 함께 `"mail_recent_hours": [8, 18]` 을 넣으면 그 시각(이후 첫 점검, 최대 30분 안)에 **기본(Primary) 탭의 안 읽은 새 메일** 최신 `mail_recent_max`(기본 5)건을 `보낸 사람: 제목` 으로 알려 줍니다.
- 지난 `mail_recent_window_hours`(기본 12)시간 안의 메일만 봅니다. 이미 알린 메일은 다시 보내지 않습니다.
- 더 있으면 마지막 줄에 "…이 외에 N건 더" 로 알립니다. 보고 싶지 않은 발신자는 `"mail_block": ["spam.kr", "a@b.kr"]`.
- 각 시각은 하루에 한 번만 확인합니다(실패하면 다음 점검에서 재시도). 허용 발신자(`mail_senders`)와 같이 쓰면 둘 다 보냅니다.
- 미리보기: `python -m aide heartbeat` 는 시각과 상관없이 요약을 보여 줍니다(전송·기록 없음).
- 모든 발신자의 제목이 텔레그램으로 전달되고 스팸 제목도 보일 수 있으니, 링크를 누르기 전에 보낸 사람을 확인하세요.

## 저녁 정리
`config.json` 에 `"evening_hour": 20` 을 넣으면 그 시각 이후 첫 점검(최대 30분 안)에 하루 한 번, 아래를 한 메시지로 보냅니다(기본은 꺼짐).
- **내일 일정** (`calendar_enabled` 일 때), **마감 임박**(접수 마감 3일 이내 공지, `notice_pages` 설정 시), **오늘 작업**(커밋), **정리할 것**(커밋 안 된 변경이 기준 이상인 폴더)
- **일요일 저녁**에는 "내일 일정" 대신 **다음 주(월~일) 일정**을 날짜별로 보여 주고, 마감 임박 범위도 7일로 넓힙니다.
- 조용한 시간(22:30~)에는 보내지 않고, 실패하면 다음 점검에서 재시도합니다. `run_heartbeat.bat` 이 함께 실행하므로 별도 예약은 필요 없습니다.
- 미리보기: `python -m aide evening` (시각 무관, 전송·기록 없음) / 지금 바로 보내기: `python -m aide evening --send --force`

## 기억 (`/기억`)
`config.json` 에 `"memory_enabled": true` (기본 꺼짐, `commands` 도 필요)를 넣으면 **본인의 개인 채팅**에서 직접 쓴 글만 기억해 둘 수 있습니다.

- `/기억 교육청 공문은 항상 중요` → `기억했어요: …` + [↩ 취소] 버튼
- `/기억` → `■ 기억 (N/50)` 목록 + 항목마다 [🗑 N] 삭제 버튼 (영문 `/remember`)
- 문장으로 묻기(`chat_enabled`)와 LLM 중요도 판단·오늘의 핵심에 **참고용 배경**으로 붙습니다. 모델 출력은 이전처럼 닫힌 값뿐입니다.
- 메일·뉴스·일정 같은 외부 글은 자동으로 저장하지 않습니다. 적은 내용은 **AI(Anthropic)로 전송**되니 비밀번호·개인정보는 쓰지 마세요.
- 한도: 50개, 한 항목 200자, 메시지 230자. `/명령` 과 같은 횟수 제한을 씁니다. 저장 파일은 `data/memory.json`(깃 제외). `selfcheck` 에서 개수만 확인할 수 있습니다.
- 자세한 설계·보안은 `ARCHITECTURE.md` 의 "기억", `SECURITY.md` 의 "기억".
